# DESIGN SYSTEM: Живое Городище

## 1. Визуальное направление

Основной референс: `Референс.png`.

Стиль: историческая интерактивная карта, темная навигация, пергаментные панели, приглушенные природные цвета, теплые акценты, компактные интерфейсные элементы.

Сайт должен выглядеть как рабочий интерактивный инструмент, а не как рекламный лендинг.

## 2. Общая композиция

### Desktop

Главный экран:

- темный header сверху;
- карта занимает основной визуальный объем;
- карточка выбранного здания поверх карты;
- справа может быть панель статистики;
- ниже карты список объектов поселения.

### Mobile

Главный экран:

- компактный header;
- карта как основной экран;
- маркеры крупнее и проще;
- карточка здания открывается bottom sheet;
- подробная страница здания доступна отдельным переходом.

## 3. Цвета

Рекомендуемые CSS tokens:

```css
:root {
  --color-ink: #17130f;
  --color-ink-soft: #2a241d;
  --color-parchment: #ead9bd;
  --color-parchment-light: #f3e6cf;
  --color-parchment-dark: #d6bd94;
  --color-forest: #38462d;
  --color-forest-dark: #26311f;
  --color-moss: #6f7b45;
  --color-gold: #c49a5a;
  --color-clay: #8b5e35;
  --color-ember: #c56a33;
  --color-border: rgba(58, 45, 31, 0.22);
}
```

Важно не уходить в однотонную бежевую палитру. Темная навигация, зеленые акценты, золотистые маркеры и теплые изображения должны балансировать пергамент.

## 4. Типографика

Рекомендуемо:

- Заголовки: serif-шрифт с историческим характером.
- Интерфейс и формы: читаемый sans-serif.
- Числа и статусы: sans-serif.

Варианты:

- Заголовки: `Cormorant Garamond`, `Lora`, `Georgia`.
- UI: `Inter`, `Manrope`, `system-ui`.

Размеры:

- H1 desktop: 40-56px.
- H1 mobile: 30-36px.
- H2: 28-36px.
- Card title: 20-24px.
- Body: 15-17px.
- Small UI: 12-14px.

Не масштабировать шрифты через viewport width.

## 5. Основные компоненты

### Header

Состав:

- знак/эмблема;
- название `Живое Городище`;
- короткий слоган;
- навигация;
- кнопка входа.

Desktop:

- высота 72-84px;
- темный фон;
- тонкая нижняя граница.

Mobile:

- логотип слева;
- burger справа;
- меню раскрывается поверх или отдельной панелью.

### Карта

Карта — главный элемент продукта.

Требования:

- изображение должно занимать всю доступную ширину секции;
- маркеры позиционируются в процентах;
- карта не должна быть помещена в декоративную карточку;
- затемнение/оверлей допустим только для читаемости маркеров;
- на mobile карта должна оставаться интерактивной.

### Маркер

Состав:

- круглая или каплевидная форма;
- иконка;
- статусная обводка;
- подпись рядом или внутри extended state.

Состояния:

- default;
- hover;
- selected;
- disabled/hidden только в админке;
- focus-visible.

Цвета по статусу:

- Замысел: серо-синий или приглушенный каменный;
- Сбор открыт: золотой;
- Строится: теплый охристый;
- Завершение: светлый бежевый;
- Действует: зеленый.

### Карточка здания

Состав:

- иконка;
- название;
- зона;
- изображение;
- описание;
- прогресс;
- сумма;
- CTA;
- ссылка на подробную страницу.

Визуально:

- пергаментный фон;
- радиус до 8px;
- тонкая текстурная граница;
- тень мягкая, не глянцевая.

### Прогресс-бар

Состав:

- подпись процента;
- собранная сумма;
- цель;
- горизонтальный бар.

Цвет:

- фон: темный прозрачный бежевый;
- заполнение: лесной зеленый или мох.

### Слот поддержки

Состав:

- миниатюра;
- название;
- цена;
- остаток;
- кнопка выбора.

Состояния:

- available;
- selected;
- funded;
- hidden только для админки.

### Летопись

Состав:

- имя или `Тайный доброхот`;
- тип события;
- объект;
- сумма или часы;
- время;
- короткий текст.

Стиль:

- компактная вертикальная лента;
- без избыточных декоративных карточек;
- хорошо сканируемые строки.

### Bottom Sheet

Используется на mobile для карточки здания.

Требования:

- высота по контенту;
- max-height около 75vh;
- drag handle;
- кнопка закрытия;
- CTA всегда доступен;
- контент скроллится внутри панели.

## 6. Админка

Админка должна быть спокойной и рабочей.

Не использовать избыточную декоративность публичной части. Допустимы:

- светлый или нейтральный фон;
- таблицы;
- формы;
- панели;
- tabs;
- filters;
- compact controls.

Важно:

- предсказуемая навигация;
- плотность информации;
- понятные статусы;
- быстрые действия;
- подтверждение опасных операций.

## 7. Иконки

Использовать `lucide-react`, если есть подходящая иконка.

Рекомендуемые соответствия:

- Кузница: `Hammer`;
- Огороды: `Leaf`;
- Жилые избы: `House`;
- Курятник: `Bird`;
- Общинный навес: `Tent`;
- Таверна: `Beer`;
- Тренировочная площадка: `Sword`;
- Колодец: `Bucket`;
- Летопись: `ScrollText`;
- Волонтеры: `Users`;
- Донаты: `Heart`;
- Вход: `CircleUserRound`.

Если lucide недостаточно, админка должна позволять загрузить кастомную иконку.

## 8. Адаптивные правила

Breakpoints:

- mobile: 360-767px;
- tablet: 768-1023px;
- desktop: 1024px+;
- wide: 1440px+.

Правила:

- текст в кнопках не должен обрезаться;
- карточки не должны вкладываться в карточки;
- fixed-format элементы должны иметь стабильные размеры;
- маркеры должны оставаться не меньше 40px touch target;
- формы должны быть удобны на 360px.

## 9. Состояния интерфейса

Для каждого основного экрана нужны:

- loading;
- empty;
- error;
- success;
- unauthorized;
- forbidden.

Особенно важно:

- карта не загружена;
- нет активной карты;
- у здания нет слотов;
- платеж pending;
- платеж failed;
- webhook еще не подтвердил оплату.

## 10. Ассеты проекта

Текущие исходные материалы:

- `Референс.png` — главный UI-референс;
- `assets/Здания/Посление_реф.png` — карта без иконок;
- `assets/Здания/Поселение_с_иконками_реф.png` — карта с иконками;
- `assets/Здания/поселение_1.png` — карта поселения;
- изображения зданий 1448x1086.

Для web рекомендуется:

- конвертировать PNG в WebP/AVIF;
- сохранить оригиналы;
- использовать responsive sizes;
- для главной карты задать priority/preload;
- для карточек использовать lazy loading.
