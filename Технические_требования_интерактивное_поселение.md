# 1. Общая концепция продукта

Платформа представляет собой интерактивную карту строящегося исторического поселения. Посетитель видит карту, кликает на здание, читает описание, выбирает конкретный объект для поддержки внутри здания, оплачивает вклад и попадает в цифровую летопись проекта.

Администратор должен иметь возможность управлять всей публичной частью сайта из админ-панели: загружать карту, ставить отметки, добавлять иконки, создавать здания, добавлять вложенные объекты сборов, менять тексты, изображения, цены, статусы, прогресс и видимость.

> **Важно:** Сайт нельзя проектировать как статичный лендинг. Карта, здания, слоты, тексты, изображения, цены и статусы должны храниться в базе данных и редактироваться в админке.

## 3.3 Пожертвования и поддержка

- Пользователь выбирает конкретный объект сбора внутри здания: например, “Горн кузницы”, “Наковальня”, “Кровля”, “Сруб”.

- Система открывает форму: имя, email, телефон опционально, сумма, согласие на обработку персональных данных, видимость имени в летописи.

- После оплаты через ЮКассу пользователь попадает на страницу успешной оплаты.

- Имя участника и вклад появляются в летописи только после подтверждения платежа webhook-событием.

- Пользователь получает email-подтверждение и ссылку на сертификат/страницу вклада.

## 5.3 Иконки и визуальные статусы

- Администратор может загрузить собственные иконки для типов зданий: кузница, дом, огород, курятник, мастерская, таверна и т.д.

- Иконки должны храниться в медиа-библиотеке и переиспользоваться разными зданиями.

- Для здания должен быть статус: “Замысел”, “Сбор открыт”, “Строится”, “Завершение”, “Действует”, “Архив”.

- Статус влияет на цвет/обводку отметки и текст в карточке.

- Администратор может вручную менять статус здания.

# 6. Здания и объекты сборов

## 6.1 Сущность “Здание”

Здание — это крупный объект на карте: Кузница, Огороды, Курятник, Изба, Таверна, Торговый ряд и т.п. У здания есть публичная карточка, страница, отметка на карте и список вложенных объектов сборов.

| **Поле**             | **Тип**       | **Комментарий**                                              |
|----------------------|---------------|--------------------------------------------------------------|
| Название             | string        | Например: Кузница                                            |
| Slug                 | string        | URL: /objects/kuznica                                        |
| Зона                 | enum          | Ремесленная, жилая, общественная, хозяйственная и т.д.       |
| Краткое описание     | text          | Для карточки на карте                                        |
| Полное описание      | rich text     | Для страницы здания                                          |
| Историческая справка | rich text     | Опциональный образовательный блок                            |
| Главное изображение  | image         | Обложка карточки и страницы                                  |
| Галерея              | images\[\]    | Дополнительные изображения и фотоотчёты                      |
| Иконка               | image/svg/png | Для отметки на карте                                         |
| Координаты X/Y       | number %      | Положение отметки на карте                                   |
| Бюджет               | money         | Может считаться из объектов сборов или задаваться вручную    |
| Собрано              | money         | Считается из оплаченных донатов                              |
| Статус               | enum          | Замысел, сбор открыт, строится, завершение, действует, архив |
| Публичность          | boolean       | Показывать/скрывать на сайте                                 |

|---------|----------------------------------------------------------------------------------------------|---------------|--------------------------------------------------------------------------|
| ITEM-01 | Администратор может добавить несколько объектов сбора к одному зданию.                       | Must          | В карточке здания отображается список объектов сбора.                    |
| ITEM-02 | У каждого объекта сбора есть название, описание, изображение, цена/цель, количество, статус. | Must          | Все поля редактируются в админке.                                        |

# 8. Волонтёры и заявки

- На публичном сайте должна быть форма заявки волонтёра: имя, email, телефон, навыки, желаемые даты, комментарий, выбранное здание/объект.

- Администратор видит заявки в админке и может менять статус: новая, в обработке, подтверждена, отклонена, отработана.

- После заезда администратор может указать количество часов, объект работ и комментарий.

- Система начисляет баллы участнику за подтверждённые часы.

- Волонтёрские вклады могут отображаться в летописи наравне с денежными.

# 10. Аналитика и отчётность

- KPI: всего собрано, доноров, средний чек, активных объектов, открытых объектов сбора, новых заявок волонтёров.

- Таблица зданий: цель, собрано, процент, количество доноров, последний вклад, статус.

- Таблица объектов сборов: здание, название, цель, собрано, остаток, конверсия, статус.

- Экспорт CSV по донатам, участникам, объектам, волонтёрам.

- Журнал действий администраторов: кто, когда и что изменил.

# 13. Безопасность и юридические требования

- Все административные маршруты закрыты авторизацией и проверкой роли.

- В Supabase должны быть включены RLS-политики для пользовательских и административных данных.

- Все загрузки файлов проверяются по типу, размеру и расширению.

- Webhook ЮКассы должен проверять подлинность и идемпотентность события.

- Должен вестись admin_audit_log для критичных действий: изменение карты, цен, платежей, ролей, скрытие записей.

- На сайте должны быть опубликованы политика конфиденциальности, согласие на обработку персональных данных и оферта/условия пожертвования.

- Персональные данные: email, имя, телефон, история платежей. Доступ к ним только у админов с соответствующей ролью.

# 16. Критерии готовности MVP

- Администратор загружает новую карту, делает её активной, и она появляется на публичной главной странице.

- Администратор создаёт здание, ставит отметку на карте, загружает иконку, описание и изображения.

- Администратор добавляет к зданию несколько объектов сбора: например, горн, наковальня, сруб, кровля.

- Пользователь кликает отметку здания, видит карточку, открывает страницу здания и выбирает объект сбора.

- Пользователь оплачивает вклад, после webhook прогресс обновляется, а запись появляется в летописи.

- Администратор видит донат, статус платежа, объект сбора, email пользователя и может экспортировать данные.

- Администратор может скрыть объект, изменить текст, цену, изображение, статус и порядок отображения без изменения кода.

- Волонтёр отправляет заявку, администратор подтверждает её и начисляет часы.

- Все критичные действия администратора записываются в журнал аудита.

- Сайт корректно работает на мобильном устройстве.
